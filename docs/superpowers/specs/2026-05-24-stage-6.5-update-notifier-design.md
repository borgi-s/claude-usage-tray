# Stage 6.5 — Update Notifier (GitHub Releases API)

**Status:** design approved 2026-05-24. Target tag `v0.6.5`.

## Goal

Notify the user when a newer release of `claude-usage-tray` is available on GitHub,
without ever downloading or self-replacing the binary. The app checks
`GET /repos/borgi-s/claude-usage-tray/releases/latest` on startup and at most once
per day while running, compares the returned tag against the compiled-in version, and
surfaces a newer release three ways:

1. A persistent **"Update available — vX.Y.Z"** item prepended to the tray right-click menu; clicking it opens the release page in the default browser.
2. A **one-time balloon notification** per new version (so a release is actively noticed, not just discoverable on right-click).
3. An always-present **"Check for updates now"** menu item that forces an immediate check and reports the result via balloon (including "you're up to date").

This realizes the Stage 6.5 row of the master design spec
(`2026-05-22-rust-tray-widget-design.md`), with the surfacing/manual-check details
resolved here.

## Non-goals

- ❌ Auto-download / self-replacement — explicitly out of scope per the master spec. Notify only; the user downloads from GitHub Releases.
- ❌ Prerelease / beta channels — `releases/latest` excludes drafts and prereleases, and that is the intended behavior.
- ❌ Config-file opt-out / disable switch — YAGNI for a single-user tool. Can be added later if needed.
- ❌ Signature / checksum verification of the released binary.

## Decisions (from brainstorming)

| Decision | Choice |
|---|---|
| How a newer release is surfaced | Persistent menu item **+** one-time balloon per version **+** manual "Check for updates now" item |
| When the auto-check runs | On start, then at most once per 24h while running |
| Which thread runs the auto-check | The existing background **poller thread** (blocking HTTP never touches the UI thread) |
| Manual check mechanism | A throwaway **one-shot thread** spawned on the menu click — instant, bypasses the 24h gate |
| Manual check rate limit | **Max 5 per rolling hour**, enforced in-memory on the UI thread (not persisted) |
| UI communication | A **new `UpdateEvent` channel + `WM_APP_UPDATE` message**, sibling to the existing `PollEvent` / `WM_APP_POLL` pattern |
| Version comparison | `semver` crate |

## Architecture

### Module layout

```
src/updater/
  mod.rs       — public API: check_latest(), types (ReleaseInfo, UpdateCheck, UpdateEvent)
  github.rs    — network: fetch_latest_release() via ureq; parse_release(json) (pure)
  version.rs   — tag→semver parsing + is_update_available() (pure)
src/state.rs   — AppState struct, load()/save() for ~/.claude-usage-tray/state.json
```

`updater` owns "is there a newer release?". `state` owns the small persistent JSON and
is kept separate because the master spec earmarks `state.json` for future dashboard
window geometry (Stage 6 open question) — so it is a general app-state file, not an
updater-private one.

### Data types

```rust
// updater/mod.rs
pub struct ReleaseInfo {
    pub tag: String,          // raw tag_name, e.g. "v0.8.0"
    pub version: Version,     // semver::Version parsed from the tag (leading 'v' stripped)
    pub html_url: String,     // release page URL
}

pub struct UpdateCheck {
    pub latest: ReleaseInfo,
    pub is_newer: bool,       // latest.version > current
}

// Sent UI-ward over the new channel, sibling to PollEvent.
// `notify` is computed by the sender (the only owner of state.json), so the UI
// thread never reads or writes persistent state — it just renders.
pub enum UpdateEvent {
    Result { check: UpdateCheck, notify: bool },
    Failed { manual: bool, msg: String },
}
```

### State ownership (single writer)

`state.json` has exactly one owner: the **poller thread**. It loads `AppState` at startup,
holds it in memory, and is the only thread that writes the file. This avoids a
lost-update race between the poller, the UI thread, and the manual-check thread.
Consequences:

- The **UI thread never touches `state.json`.** It reacts only to `UpdateEvent`. The
  balloon decision is made by the sender and carried in the `notify` flag.
- The **manual one-shot thread is stateless** — it performs the network check and sends
  an event with `notify = true` (manual results are always shown). It does not read or
  write `state.json`. It therefore does not update `last_check`; at worst the scheduled
  auto-check fires once more shortly after, which is harmless.

### Persistent state — `state.json`

```json
{
  "update": {
    "last_check": "2026-05-24T12:00:00Z",
    "last_notified_version": "0.8.0"
  }
}
```

- `AppState` is a `serde` struct with a nested `update` section.
- `state::load()` returns `AppState::default()` if the file is missing or corrupt — log a `tracing::warn!`, never fail startup.
- `state::save()` writes via `paths::ensure_parent_dir` + `serde_json::to_string_pretty`.
- New `paths::state_path()` → `~/.claude-usage-tray/state.json`.
- `last_check` (UTC, optional) gates the daily auto-check.
- `last_notified_version` guards the once-per-version balloon.

### Check flow

`updater::check_latest(current: &Version) -> Result<UpdateCheck, UpdateError>`:

1. `fetch_latest_release()` — `GET https://api.github.com/repos/borgi-s/claude-usage-tray/releases/latest`
   with headers `User-Agent: claude-usage-tray/<CARGO_PKG_VERSION>` (GitHub 403s without a
   User-Agent) and `Accept: application/vnd.github+json`.
2. `parse_release(json)` — extract `tag_name` and `html_url`; strip a leading `v`
   (`v0.8.0` → `0.8.0`); `Version::parse`.
3. Compare → `is_newer = latest.version > *current`.

**Auto path** (in `src/tray/poller.rs`, on the poller thread — sole owner of `state.json`):
after each `poll_once`, read the in-memory `state.update.last_check`. If `None` or older
than 24h, call `check_latest(current, manual = false)`, then set `last_check = now` and
`save()` regardless of the outcome (so a failed check still throttles retries to daily).
On `Ok`, compute `notify = is_newer && latest.version != last_notified_version`; if
`notify`, set `last_notified_version = latest.version` and `save()`. Then send
`UpdateEvent::Result { check, notify }` over the channel and
`PostMessageW(hwnd, WM_APP_UPDATE, ..)`. Network/parse errors → `tracing::warn!` and
swallow — never disturb usage polling.

**Manual path** (spawned from the UI thread, runs off-thread): the `IDM_CHECK_UPDATES`
menu click spawns a one-shot `thread::spawn` that calls `check_latest(current, manual =
true)` — ignoring the 24h gate — and sends `Result { check, notify: true }` / `Failed`
over the same channel + posts `WM_APP_UPDATE`. It is stateless (see *State ownership*):
it does not read or write `state.json`. Both paths hold a clone of `Sender<UpdateEvent>`
and a `Send`-wrapped `HWND`.

### UI integration (`src/tray/window.rs`, `src/tray/icon.rs`)

New constants:
- `WM_APP_UPDATE = WM_APP + 3`
- menu item IDs: `IDM_UPDATE = 2`, `IDM_CHECK_UPDATES = 3` (existing `IDM_QUIT = 1`)

`TrayState` gains:
- `update_rx: Receiver<UpdateEvent>`
- `update_tx: Sender<UpdateEvent>` (cloned into the manual thread)
- `available_update: Option<ReleaseInfo>` (UI-thread-local; for the menu item — not persisted)
- `manual_check_history: Vec<Instant>` (UI-thread-local; timestamps of recent manual checks, for the rate limit — not persisted)

`WM_APP_UPDATE` message arm — drain `update_rx` (the UI thread never touches `state.json`;
it acts purely on the event):
- `Result { check, notify }` where `check.is_newer` → store `available_update =
  Some(check.latest)`. If `notify`, fire a balloon *"Update available — v0.8.0 · click
  the tray to open"*. (The sender already guarded the once-per-version logic, so `notify`
  is false on a repeat auto-detect and true on any manual check.)
- `Result { check, notify: true }` where `!check.is_newer` → balloon *"You're up to date
  (v<current>)"* (this only occurs on a manual check, since the auto path sends
  `notify: false` when not newer).
- `Result { notify: false, .. }` where `!is_newer` → nothing.
- `Failed { manual: true, .. }` → balloon *"Update check failed"*.
- `Failed { manual: false, .. }` → already logged; ignore.

`<current>` in balloon text is `env!("CARGO_PKG_VERSION")`.

`show_context_menu` now reads `TrayState` (via `with_state`):
- if `available_update.is_some()`, prepend `Update available — vX.Y.Z`;
- always append a separator + `Check for updates now` + `Quit`.

`WM_COMMAND` arm:
- `IDM_UPDATE` → `ShellExecuteW(None, "open", <html_url>, .., SW_SHOWNORMAL)` opens the
  release page in the default browser.
- `IDM_CHECK_UPDATES` → enforce the manual rate limit (see below), then spawn the manual one-shot thread if allowed.
- `IDM_QUIT` → unchanged.

**Manual-check rate limit — max 5 per rolling hour.** Before spawning the manual thread,
the UI thread calls a pure helper `manual_check_allowed(history: &mut Vec<Instant>, now:
Instant) -> bool`: it prunes entries older than 1 hour, and if fewer than 5 remain, pushes
`now` and returns `true`; otherwise returns `false`. On `false`, no thread is spawned and a
balloon *"Update-check limit reached — try again later"* is shown. The window is in-memory
only (`Instant`-based, monotonic); a restart resets the budget, which is acceptable for an
abuse guard. The auto (daily) check is unaffected by this limit.

Balloon helper — new `icon::show_balloon(hwnd, title, msg)`: `Shell_NotifyIconW(NIM_MODIFY)`
on the existing `NOTIFYICONDATAW` with the `NIF_INFO` flag set and `szInfo` / `szInfoTitle`
populated (UTF-16, null-terminated, within the Win32 length caps). `Win32_UI_Shell` is
already enabled and also provides `ShellExecuteW` — no new crate features required.

## Error handling

- `updater` exposes a `thiserror`-derived `UpdateError` enum (`Http`, `Parse`, `Version`).
- Both the poller-thread auto path and the manual one-shot thread map errors to
  `UpdateEvent::Failed` (manual) or `tracing::warn!` (auto). Neither panics; neither
  blocks the UI thread.
- `state::load` failures degrade to defaults; `state::save` failures log a warn and are
  non-fatal.

## Testing

Pure functions only — no network in tests:
- `parse_release()` against a saved GitHub `releases/latest` JSON fixture in `tests/fixtures/`.
- tag parsing: leading-`v` strip, plain `0.8.0`, malformed tag → error.
- `is_update_available()` / version comparison: newer, older, equal.
- `AppState` serde round-trip; missing-file → `default()`; corrupt-file → `default()` + warn.
- `manual_check_allowed()`: allows the first 5 within an hour, rejects the 6th, allows again once an entry ages past the 1-hour window (drive with injected `Instant`s).

Win32 menu, balloon, and `ShellExecuteW` paths are visual/side-effecting — smoke-tested by
running, consistent with the project's "no unit tests for Win32/egui" convention.
